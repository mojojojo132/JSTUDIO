# One project, connected production

Run commands from the installed runtime. Paths are resolved from STUDIO.json; do not create film assets inside runtime. The editor is neutral. Output branding comes from the project's pinned brand snapshot, originally selected from Studio Brand Packs.

`npm run workflow -- <slug> status` returns the project/native paths, pinned brand, current/stale review records, exchange check and next actions. A clean technical check is never creative approval.

1. Create/resume one project with `npm run new -- <slug>` and `npm run workflow -- <slug> init`. Record the initiating request verbatim with optional `--initiator <known-actor> --request-file <path>`; unknown identity remains unknown. Keep concise brief/storyboard and interaction records in the configured project.
2. Plan within the authorized brief. Storyboard registration/approval is available for requested intermediate decisions, not a prerequisite to render a complete candidate. Do not include administrative logs, status or construction notes in render dependency inventories.
3. Prepare Animator with `npm run workflow -- <slug> animation new` and `animation setup`; render through `animation render`. Generate/register versioned shot descriptors with exact source/config/asset inventories, measured media, engine identity and render settings. Inspect the actual results internally.
4. `npm run workflow -- <slug> import <shot-id> --review-only` stages current immutable clips without claiming approval. Open `npm run workflow -- <slug> edit` and assemble the complete intended picture, narration, captions and mix. The normal approved-import route remains available for previously approved clips.
5. Write EXCHANGE using the returned exact source revision/fingerprint/hash and actual native bindings. `npm run workflow -- <slug> exchange <contract.json> --review-only` validates and records candidate staging. Preserve source/media integrity, canvas/FPS, timing, trims and audio policy; review-only is not permission to publish or deliver as approved.
6. Run `npm run workflow -- <slug> preflight --review-only`, then `npm run workflow -- <slug> render --review-only --output ../reviews/candidates/v001.mp4`. Output is relative to the native directory. Internally review this complete encoded candidate against the full brief before presenting it.
7. Register the exact cut and available assessment with `npm run workflow -- <slug> prepare-review main <cut-descriptor.json> [assessment.json] --no-editor` (omit `--no-editor` when an editor handoff is useful). Record the actual decision with `npm run workflow -- <slug> approve cut main <evidence.json>`. Evidence identifies the returned fingerprint and actual user statement; “Approved” suffices when the candidate is unambiguous, without a separate watched/listened declaration.
8. `npm run workflow -- <slug> deliver delivery/<filename>.mp4` copies/promotes the approved candidate bytes and verifies identity. It does not render. Show that delivered file in chat; changed bytes require a new candidate decision. External publication/sharing still requires separate authorization.

Descriptor/evidence paths are relative to the project. Storyboard/cut ID is `main`; shot IDs are stable lowercase slugs. Optional storyboard descriptor minimum: `{ "files": ["STORYBOARD.md"] }`. Cut descriptors identify the complete encoded media and its measured settings; approval binds its bytes, while sourceSnapshot retains provenance. Shot descriptors also require `media`, `engineRevision`, `renderSettings`; all source and asset dependencies must be listed. Evidence requires `reviewer`, exact `statement` with source, and `fingerprint`. Never manufacture evidence, interpret workflow authorization as film approval, or treat synthetic-test records as user approvals.

New managed projects cannot CLI-export imported animation without EXCHANGE.json. Footage-only edits without managed animation imports remain supported; record animation as not applicable in the storyboard. Legacy projects are not silently converted. Editor exports must use the installed finishing guard and produce a finishing receipt; if the installed build lacks that guard, use the guarded workflow render route instead. Verify the encoded result before delivery. Dynamic video bindings/repeated linked compositions need explicit rendered verification; do not remove the exchange to evade a failing check.

Commands produce scoped run reports with token fields and unavailable reasons when host telemetry is absent. Status is read-only; render uses the existing render report. The supervising AI must additionally report whole-run root/subagent telemetry according to [run reporting](run-reporting.md).

## Exact-render review and gate reports

`npm run workflow -- <slug> review assessment.json` records exact-media review evidence; see [assessment schema and honest capability coverage](render-review.md). Shot/cut approval evidence may carry `reviewReceipt` alongside the actual user’s approval evidence; its absence never authorizes invented perception. `npm run workflow -- <slug> gate <storyboard|animation|final> [review-receipt.json|-] [telemetry.json]` captures status and scoped accounting at the existing review gate. Neither command creates approval or a new review stage.

Generate shot descriptors with `npm run workflow -- <slug> descriptor reviews/animation/shot-v001.mp4 settings.json evidence/shot-v001.descriptor.json`. Settings supply `engineRevision`, `renderSettings` and optional provenance/extra `files`. The generator inventories source, engine, pinned assets and media; all asset paths belong in `files`, never a `dependencies` field. Registration rejects unsupported fields. Outputs are exclusive: choose a new filename for each revision.

Before registering a production shot, render a new version through `workflow <slug> animation render video --project projects/<config>.json --out <absolute-project-output.mp4>`. The render writes `<output>.render.json` with before/after input hashes and the output hash. The descriptor and registration verify these bytes; do not fabricate a sidecar for an old render. Review packs remain diagnostic and are not registration outputs. Older unapproved shots need a fresh render/descriptor/revision; existing approved history is retained. Render inputs are conservatively inventoried, so unrelated animation source changes can require rerendering. Finish authoring stable source before rendering a batch; do not weaken dependency checks to avoid that work.

For the default complete-candidate presentation, use the exact review receipt with `gate final` when available; optional storyboard/animation decisions retain their report commands. Creative approval and perceptual-review completeness are distinct: missing/unavailable continuous playback or listening does not force another user attestation. Record actual limitations, never fabricate coverage. Optional reviewReceipt evidence is checked if supplied; it is not itself approval.

Use `npm run workflow -- <slug> context <intake|animation|finishing|review>` for a bounded hashed packet. Gate reports also retain a STAGE-CONTEXT.json snapshot automatically. Read missing or truncated authoritative records as needed; a compact packet is not approval evidence. Status reports native and animation brand integrity separately and does not require an unrelated animation workspace to be healthy merely to finish an unchanged approved clip.

## Internal proofs and media readiness

Within the authorized brief, run `npm run workflow -- <slug> proof render reviews/proof/<version>` for an isolated transition experiment. See [internal proofs](internal-proofs.md). This route does not require complete-animation approval and does not create production approval/import records. Do not bypass the wrapper when a proof cannot use the production native directory.

For final assembly, declare recorded footage and sound in EXCHANGE `media` bindings; see [media integrity](media-integrity.md). An omitted media list retains legacy behavior but does not certify untracked files. Capture validation must use encoded dimensions/frame rate/duration, not viewport assumptions. Scripted interactions with a real functioning interface qualify as recorded interactions when disclosed; human input is required only when the brief specifically requests it.

Run `npm run media:check -- <absolute-project> <assessment.json>` for shared decode/measurement and `npm run font:check -- <absolute-project> <assessment.json>` for exact-copy font readiness. Inspect their receipts and limitations. Font loading alone does not establish glyph coverage; do not silently change approved copy when a glyph is absent. Measurements never establish playback/listening or rights clearance.


For an existing project's engine, use `workflow <slug> animation update-engine` to inspect a read-only upgrade plan. `--apply` updates only unchanged managed engine files and retains backups; conflicts require review, never automatic overwrites. Scenes, project configs, packs, media and approval ledgers are preserved. Core changes intentionally stale source-bound registrations; render and review a new version. Dependency changes require a separately validated migration. Runtime deployment alone upgrades the template for new projects, not existing project engine copies.

## Prepare a complete review handoff

Use `npm run workflow -- <slug> prepare-review main cut-descriptor.json assessment.json` to register the exact encoded cut, record its assessment and capture gate state, then start or reuse the native preview with `--background --no-open`. Omit the assessment when review remains unavailable; the result should expose missing steps rather than invent evidence. Use `--no-editor` only when the current task does not need an editor. Follow the returned URL through the host's supported tab tool; a server starting is not evidence that a tab opened. Record actual playback, seeking, layer selection and saved editing changes separately.

A generic “Approved” establishes creative approval of the unambiguously identified candidate. It never establishes that someone watched or listened. `workflow attest assessment.json` is optional when the user has actually provided an explicit complete-viewing/listening statement; retain its exact quote, reviewer, source and media hash. Do not solicit formulaic attestations as a routine extra gate. Changed media needs a new creative decision and fresh perceptual evidence for any such claim.

Read `status` before a stage transition; address named missing readiness items. Blank planning templates are not completed planning. Keep concise substantive notes on the intended viewer outcome, causal beats, selected brand, hardest transition, mobile reading size and observed defects/refinements. Link evidence instead of repeating it across documents; do not add approval gates for these internal working notes.
