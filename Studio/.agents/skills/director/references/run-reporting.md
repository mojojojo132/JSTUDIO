# Run reporting

Every production or Studio engineering run report must include measured token details or explicit unavailable reasons. From the Studio runtime use `node scripts/run-report.mjs --input <explicit-run-telemetry.json> --output <new-report.json>`. Preserve each report; do not overwrite an earlier run. The tool also writes a Markdown companion. Use actual host/provider usage records for the exact run interval; do not scan unrelated conversations. If the host exposes no usage, record that limitation rather than estimating.

Input schema: `schemaVersion: 1`, `runId`, `startedAt`, `endedAt`, `participantInventoryComplete`, `measurementScopeComplete`, `participants: [{id, role}]`, and incremental `entries`. Each entry records `id`, `participantId`, `model`, `stage`, `attempt`, `startedAt`, `endedAt`, `source: {kind, reference, recordId}`, `tokens: {input, cachedInput, output, reasoningOutput, total}`, and `unavailableReasons` for unavailable fields. Follow CLI validation for supported evidence sources. Input includes cached input; output includes reasoning output. Never add those subsets again. Convert cumulative snapshots into verified interval deltas before ingestion; do not sum cumulative records.

When actual cost is exposed, include `cost: {amountMicros, currency, source: {kind, reference, recordId}}` on the matching incremental entry. `amountMicros` is the exact amount in millionths of the stated ISO 4217 currency unit; supported evidence kinds are `provider-billing`, `provider-invoice`, `billing-export` and `host-billing`. Use actual provider/host billing evidence only. For unavailable cost, leave amount/currency/source null and state `unavailableReason`. Token and cost coverage are separate; never derive cost from tokens or pricing tables, and never combine different currencies into one total.

Include root and child agents, failed attempts and retries, models and stages. Add a missing-metrics entry for every participant whose telemetry is unavailable. Set `measurementScopeComplete` true only when all calls/attempts in the declared scope are accounted for. Distinguish complete participant inventory from complete measured token coverage. A partial measured subtotal is not the run total. Missing child telemetry must remain visible. Tool/process-only receipts cannot establish AI usage; report their coverage as such. Costs are not tokens, and cannot be invented without actual billing evidence.

At handoff, attach the report to the existing verification receipt or project log; do not create a second narrative report repeating all production records. Subagents return artifact paths, changed behavior, tests, unresolved issues and their usage evidence/availability. Keep prompts scoped to the current stage and file ownership, avoiding repeated full policy dumps.

## Existing review gates

Before presenting an existing storyboard, complete-animation or final-cut review, run `npm run workflow -- <slug> gate <storyboard|animation|final> [review-receipt.json|-] [telemetry.json]`. This captures the technical state and scoped command report; attach measured conversation telemetry when available. Missing telemetry remains explicitly unavailable. This is reporting at an existing gate, not another approval stage. Record retries as they happen rather than reconstructing them only at delivery.


Gate reports now include `receiptSummary`: all recorded project commands grouped by stage/status and internal-proof receipts with unique output hashes and parse errors. Use this to substantiate counts, clearly labeling the project-wide scope; do not present it as the current conversation's activity or count receipt duplicates as additional renders. Keep retries/failed attempts separate from verified output receipts.

Every `presented-for-review` gate also writes an immutable cross-project learning packet and findings template in `evidence/improvement-packets/<packet-id>/`. Include the exact reviewed bytes, quality coverage, project command failures and token coverage in the analysis. After classifying each finding as film-only, Studio-wide or creative-system, record it with `npm run improve -- record <slug> evidence/improvement-packets/<packet-id>/FINDINGS.json`. Empty findings are valid and preserve the run's quality/telemetry summary. See `continuous-improvement.md` for privacy rules, scoring definitions and issue dispositions. Do not treat a learning packet as an approval gate or as proof that a person watched or listened.
